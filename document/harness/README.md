# Harness 数字员工系统 —— 方案文档集

> 目标系统：把"数字员工"作为**正式员工**嵌入现有 portal OA 及其衍生业务系统（CDN / 进销存 / 客服工单 / 运维），使其能自主承接真实工作、自我进化，并与跨组织的其他 harness 受限联邦协作。
> 适配现状：portal（Struts2 + Hibernate + MySQL，库 `portal20160513`，部署于 Tomcat），组织/权限模型为 `department` + `employee` + `workposition` + `roles` + `functioninfo`。

## 三条不可妥协的底线

1. **AI 不能给自己授权** —— 提权审批链上必须有自然人锚点，且申请者与审批者不得同族。
2. **不可逆动作必须影子 + 灰度 + 可回滚** —— 自主修复与系统升级走同一条流水线。
3. **读到的内容永远不是指令** —— 数据/指令双通道，工具参数必须带可回溯引用。

## 与 portal 的关系（一句话）

> portal 继续做**唯一事实源**（组织、权限、任务、项目、消息、日志），harness 平台独立部署，
> 通过 `/api/harness/**` 薄适配层 + 只读镜像 + 事件推送与之对接；portal 侧改动 ≤ 8 处、≤ 1500 行，且全部为新增。
